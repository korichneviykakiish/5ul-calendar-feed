# Calendar Feed — фид событий групп VRChat для мира 5ul

Раз в 30 минут GitHub Actions логинится бот-аккаунтом в VRChat API, забирает
события календарей групп из `groups.json` и публикует компактный
`docs/events.json` на GitHub Pages. Мир читает его через VRCStringDownloader —
домен `*.github.io` входит в доверенный список String Loading, так что
игрокам НЕ нужно включать «Allow Untrusted URLs».

Независимая копия: `korichneviykakiish/5ul-calendar-feed`.
После проверки нового бота адрес для мира:
`https://korichneviykakiish.github.io/5ul-calendar-feed/events.json`.
Старая афиша не отключается автоматически.

## Установка

1. **Бот-аккаунт VRChat.** Создай отдельный аккаунт (не основной!). Вход можно
   подтвердить кодом из почты, приложение-аутентификатор не обязательно. Вступи этим
   аккаунтом во все группы из списка — иначе он увидит только публичные события.

2. **Репозиторий GitHub.** Создай **публичный** репозиторий (Pages на
   приватном — платная фича), залей в него содержимое этой папки.

3. **Секреты.** Settings → Secrets and variables → Actions → New repository
   secret:
   | Секрет | Значение |
   |---|---|
   | `VRC_USERNAME` | логин бот-аккаунта |
   | `VRC_PASSWORD` | пароль бот-аккаунта |
   | `VRC_TOTP_SECRET` | необязательно: base32-секрет, только если на аккаунте включён TOTP |
   | `VRC_EMAIL_CODE` | временно: шестизначный код из последнего письма VRChat, для ручного подтверждения |
   | `VRC_CONTACT` | твой e-mail (обязателен в User-Agent по правилам VRChat API) |
   | `VRC_SESSION_KEY` | отдельный случайный ключ Fernet для шифрования сессии; при переносе настроен автоматически |

   Пароли, коды, ключ TOTP и ключ сессии не добавлять в файлы репозитория или логи.
   Код из письма вводить только в GitHub Secrets, не в поля Run workflow.
   При самостоятельной настройке ключ сессии можно создать через
   `cryptography.fernet.Fernet.generate_key()` и сразу сохранить в Secrets.

4. **GitHub Pages.** Settings → Pages → Source: `GitHub Actions`.
   Workflow самостоятельно публикует только папку `docs`. Фид будет доступен по адресу
   `https://<логин>.github.io/<репозиторий>/events.json`.

5. **Группы.** Впиши в `groups.json` реальные ID групп (`grp_...` — виден в
   URL страницы группы на vrchat.com). Поле `name` — только для логов,
   отображаемые имена и цвета настраиваются в Unity-окне календаря.

6. **Первый вход без TOTP.** Actions → update-calendar-feed → Run workflow →
   `login_action: request-email`. Дождись шага `EMAIL_VERIFICATION_REQUIRED`.
   Сохрани код из пришедшего письма в Repository secret `VRC_EMAIL_CODE`, затем
   запусти этот же workflow с `login_action: verify-email`. Незавершённый вход
   хранится зашифрованным; подтверждение не отправляет новое письмо.
   После успешной публикации удали временный `VRC_EMAIL_CODE`.
   Если код истёк, повтори `request-email` и замени секрет кодом нового письма.
   Проверь свежесть `docs/events.json` на Pages, затем создай Repository variable
   `FEED_ENABLED` со значением `true` для обновления по расписанию.
   До её включения работают только тесты и явно запрошенные ручные входы.
   С TOTP можно сразу включить `FEED_ENABLED` и выполнить обычный запуск `auto`.

7. **Unity.** В Unity: Tools → Calendar → Настроить календарь, вставь URL фида
   из шага 4, добавь те же группы, нажми «Собрать панель».

## Как это устроено

- Куки сессии шифруются Fernet с проверкой целостности в `state/cookies.enc`.
  В actions/cache попадает только этот зашифрованный файл, ключ остаётся в
  GitHub Secrets. Сессия привязана к логину: смена бот-аккаунта или ключа
  требует нового входа. Старые незашифрованные кэши не читаются.
  Повторный вход происходит только когда сохранённая сессия недействительна.
  Без TOTP для этого нужно вручную повторить подтверждение по почте. Плановые
  запуски не рассылают письма и не используют оставшийся старый код.
- Перед обновлением выполняются локальные тесты без обращения к VRChat.
  При ошибке сбора последний опубликованный файл не заменяется.
- Публикация Pages выполняется явно, без зависимости от того, запускает ли
  коммит через `GITHUB_TOKEN` отдельную сборку сайта.
- Скрипт ходит в API с паузами 3 с и бэкоффом на 429 — правила VRChat для
  неофициального API (внятный User-Agent + щадящий темп).
- События обрезаются: горизонт 35 дней, описание до 280 символов, символы вне
  запечённого TMP-атласа мира заменяются пробелами.
- Если события не изменились, файл не переписывается (heartbeat `gen`
  обновляется раз в 6 часов) — история коммитов не засоряется.

## Известные риски

- **API неофициальный.** VRChat терпит аккуратные интеграции, но эндпоинты
  могут поменяться без предупреждения. Красный ран в Actions = сходить сюда
  и посмотреть лог.
- **Cloudflare против IP датацентров.** Если раны стабильно падают с 403 на
  логине — GitHub-раннеры попали в блок. Варианты: self-hosted runner дома,
  запуск скрипта по расписанию на своей машине (Планировщик задач Windows),
  или запасной источник vrcwiki.ru/api/events.
- **Повторная проверка входа.** Раннеры могут менять IP, VRChat может заново
  запросить подтверждение. Без TOTP потребуется новый код из почты; полностью
  автономный вход навсегда не гарантируется. Старый фид при этом сохраняется.
